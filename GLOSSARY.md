# Project glossary

**Purpose:** Define the canonical language used by requirements, code, interfaces, documentation, issues, and conversations. **Audience:** Domain experts, product, design, engineering, operations, and AI agents. **Maintenance:** Domain and product owners review terminology changes. Update definitions when domain understanding changes and link significant decisions to their ADRs. **Related:** `.ai/shared/project-context.md`, `docs/requirements/README.md`, `docs/architecture/README.md`.

Do not invent terms to populate this template. Add a term when it is used by the project, has a project-specific meaning, or could be misunderstood.

## Domain boundaries

For a project with one domain, record `[SINGLE_DOMAIN]`. For a multi-domain repository, list each bounded context, its owner, and where its detailed glossary lives. Keep this file as the top-level map rather than duplicating every domain definition.
