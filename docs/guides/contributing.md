# Contributing

**Purpose:** Explain the shared contribution workflow. **Audience:** Human and AI-assisted contributors. **Maintenance:** Update when review, branching, release, or quality gates change. **Related:** `../../AGENTS.md`, `../development/setup.md`, `../development/coding-conventions.md`.

1. Read the relevant requirements, architecture, current state, and local instructions.
2. Link the change to an issue or agreed outcome when available.
3. Keep scope focused; discuss significant, breaking, destructive, or security-sensitive changes before implementation.
4. Never commit secrets, private data, production data, machine-local state, or unreviewed AI transcripts.
5. Add or update tests and documentation with the code.
6. Run the documented quality checks and include results and known limitations in the review description.
7. Use reviewable commits and follow the project's selected branch and commit conventions once documented.

Reviewers verify requirements, architecture fit, security/privacy, tests, operability, documentation, and backward compatibility. Approval of generated code follows the same standard as human-written code.
